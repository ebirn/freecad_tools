familiarize with the AGENTS.md and README file then start working on the tasks in TODO.md
contain your work in this repo, you don't need access to external resources, but you can use the AGENTS.md and README.md as reference for your work. The tasks in TODO.md are related to the development of the freecad_tools, which is a collection of Python utilities for working with FreeCAD designs. You can use context7 for API documentation and any other relevant information you need to complete the tasks. Make sure to follow the guidelines and best practices for Python development, and to test your code thoroughly before committing it to the repository. If you have any questions or need clarification on any of the tasks, feel free to ask.

open a develop branch in git and commit to that branch. from the development branch (only from there) you may also push to github. just keep going in an unattended way, and when you are done with the tasks, you can create a pull request to merge the develop branch into the main branch. This way we can review the changes before they are merged into the main branch, and we can also keep the main branch clean and stable.

When looking for guidence during development, check the AGENTS.md file.

The tasks include:

* macros: they should be called from within Freecad. There are Object names hardcoded, that should not be the same for every project. Maybe we can have a config file for the macros as well, or pass parameters to the macros. of if at all possible have a dialog pop up to ask the user check context7 for api docs.
* tools: they should be called from the command line, and should be able to take parameters, like the path to the .FCStd file, and the path to the export config file. This way they can be used in a pre-commit hook, but also manually by the user. They should also be able to be called from within Freecad, maybe with a button in the toolbar, or a menu item. This way they can be used by users who are not familiar with the command line.
* the exporter config takes a list of bodies to export. Is there a way to mark the bodies in freecad, so that we don't have to hardcode the body names in the config file? Maybe we can use a custom property on the bodies, or a specific naming convention. This way we can avoid having to update the config file every time we change the model.
* the exporter list of bodies should be able to specify how often it should be in the 3mf file, but no need to export the stl twice. additionally, we should be able to specify the orientation of the body in the 3mf file, so that we don't have to rotate it in the slicer. maybe we can use a custom property on the bodies to specify this as well.
* the exporter should be able to add metainformation to the 3mf file, like the project name, version, author, etc. This way we can keep track of the different versions of the model and who created them. also the git commit hash of the export (and branch and tag) would be good to have in the metainformation, so that we can easily trace back which version of the model was exported.
